# CAU Campus Typing Game 상호작용 설계

## 목적

원본 메트로 타이핑 게임의 시작 연출·입력 피드백·효과음 감각을 참고해, 축제 부스용 CAU Campus Typing Game의 플레이 경험을 보완한다. 이 문서는 2026-09-02 게임 설계의 플레이 입력 규칙을 대체한다. 백엔드 API, 세션 형식, 리더보드 규칙은 바꾸지 않는다.

## 확정 사항

- 플레이 화면 진입 뒤 `3 → 2 → 1 → START!` 카운트다운을 각각 1초 간격으로 표시한다.
- `START!`와 동시에 경과 시간 측정과 입력을 시작한다.
- 장소명은 글자마다 즉시 강제 채점하지 않는다. 플레이어는 오타를 포함한 문자열을 입력창에서 확인할 수 있다.
- 현재 장소명과 입력값의 일치 여부는 Enter 키로 제출할 때만 판정한다.
- 제출값이 정답이면 즉시 다음 장소로 진행한다. 제출값이 다르면 오타 수를 1회 늘리고 입력창 전체를 비운다.
- 입력 중인 문자열은 정답 위치의 글자는 기본색, 정답과 다른 위치의 글자는 빨간색으로 표시한다.
- 타건·정답·오타·카운트다운 효과음은 Web Audio API로 합성한다.
- 플레이 화면에 음소거 토글을 두고, 선택값은 같은 브라우저의 재도전과 새 게임에도 유지한다.

## 플레이 상태 흐름

```text
play page load
  → countdown (3, 2, 1)
  → start (timer on, input focused)
  → typing
     ├─ Enter + exact match → success sound → next place → typing
     └─ Enter + mismatch    → failure sound → typo +1 → clear input → typing
  → all places complete → completion save
```

카운트다운 중에는 입력창을 비활성화하며 타이머를 증가시키지 않는다. `START!`가 표시되는 시점에 입력창을 활성화하고 포커스를 이동한다. 음소거 버튼은 카운트다운을 포함한 전 구간에서 조작할 수 있다.

## 입력 모델

### 제출과 오타

- 실제 입력값은 네이티브 `<input>`이 보관한다. 입력 중 오타를 자동 삭제하거나 입력을 차단하지 않는다.
- Enter 키만 제출 동작이다. 입력값이 현재 장소명과 정확히 같으면 성공이다.
- 불일치 제출은 한 번의 실패 시도로 계산한다. 글자 수와 무관하게 오타 수를 1 증가시키고 입력값 전체를 초기화한다.
- Backspace와 IME 조합은 브라우저 기본 동작을 따른다. 조합 중인 한글은 제출 전까지 채점하지 않는다.
- 붙여넣기는 기존 게임 규칙에 맞춰 막는다. 붙여넣기 시도는 오타로 계산하지 않는다.

### 시각 피드백

일반 `<input>`은 텍스트 일부만 색칠할 수 없으므로, 접근 가능한 실제 입력칸과 시각 전용 표시 레이어를 같은 위치에 겹친다.

- 실제 입력칸은 포커스·캐럿·IME·스크린 리더 입력을 담당한다.
- 표시 레이어는 입력값을 문자 단위로 렌더링한다. 현재 목표의 동일 위치 문자에는 기본색을, 다르거나 목표 길이를 넘는 문자에는 오류색을 적용한다.
- 표시 레이어는 `aria-hidden="true"`로 숨긴다. 실제 입력값은 input의 접근성 트리에서 한 번만 제공한다.
- 입력칸의 글자색은 투명하게 두고 캐럿은 명확히 보이게 하여, 표시 레이어와 중복 글자가 보이지 않게 한다.
- 제출 실패 뒤에는 입력값과 표시 레이어가 모두 비워지고, 오타 수와 오류 상태 메시지를 갱신한다.

## 사운드

원본 게임 확인 결과 타이핑 처리에서 `AudioContext.createOscillator()`를 호출한다. 이 게임도 별도 음원 파일 없이 Web Audio API의 oscillator와 gain node로 짧은 효과음을 합성한다.

| 이벤트 | 재생 시점 | 의도 |
| --- | --- | --- |
| 카운트다운 | `3`, `2`, `1`, `START!` | 게임 시작 리듬을 전달 |
| 타건 | 입력 가능한 키 입력마다 | 가벼운 타이핑 피드백 |
| 정답 | Enter 제출 성공 | 명료한 상승 완료음 |
| 오타 | Enter 제출 실패 | 짧고 구분되는 하강 오류음 |

- 첫 사용자 조작 이후 `AudioContext`를 만들거나 재개한다. 브라우저 자동재생 정책으로 효과음이 실패해도 게임은 정상 진행한다.
- 음소거일 때는 AudioContext 생성·재생을 모두 건너뛴다.
- 음소거 상태는 `localStorage`의 전용 키에 boolean으로 저장한다. 저장값이 없으면 기본값은 음소거 해제다.
- 버튼은 현재 상태를 명확히 읽어 주는 `aria-label`과 pressed 상태를 제공한다. 시각 아이콘만으로 상태를 전달하지 않는다.

## 구성 경계

| 구성 요소 | 책임 |
| --- | --- |
| `typing-state` | 입력 초안, Enter 제출 결과, 오타 수, 장소 진행을 순수 함수로 계산 |
| `useCountdown` | 카운트다운 단계와 플레이 시작 시점을 관리 |
| `sound` | Web Audio 효과음, 음소거 설정 읽기·쓰기, 오디오 오류 무시 |
| `TypingInput` | 네이티브 input, 문자별 표시 레이어, Enter 제출과 IME 처리 |
| `PlayPage` | 위 구성 요소 결합, 타이머, 포커스, 완료 API 전송 |

서버에는 완료 시점의 누적 오타 수만 전송한다. 카운트다운 시간과 음소거 설정은 서버 기록에 포함하지 않는다.

## 오류 처리와 접근성

- 카운트다운 타이머가 중복 실행되거나 화면 전환 뒤 남지 않도록 정리한다.
- 오디오 생성·재생 예외는 콘솔 오류나 게임 중단으로 이어지지 않는다.
- Enter 제출 실패와 다음 장소 이동은 스크린 리더용 상태 영역으로 알린다.
- 카운트다운 완료 뒤 입력 포커스를 보장하고, 성공·실패 뒤에도 입력 포커스를 유지한다.
- `prefers-reduced-motion` 환경에서는 카운트다운 숫자의 확대·축소 애니메이션을 제거하고 단순 교체로 표시한다.

## 검증 기준

- 순수 상태 테스트: 정답 제출, 오답 제출 시 전체 초기화·오타 1 증가, 다음 장소 이동, 빈 입력 제출을 검증한다.
- 컴포넌트 테스트: 카운트다운 중 입력 비활성화, 시작 뒤 포커스, 글자별 색상 표시, Enter 제출, IME 조합 중 입력 보존을 검증한다.
- 사운드 테스트: Web Audio 객체를 모킹해 이벤트별 재생 호출과 음소거 시 미호출을 검증한다.
- 브라우저 테스트: 카운트다운부터 최소 한 장소의 성공·실패·재시도까지 확인하고, 음소거 상태가 새 게임에서도 유지되는지 검증한다.
- 현장 점검: 공용 PC의 실제 한글 IME와 물리 키보드에서 입력·Enter·효과음·음소거 버튼을 확인한다.

## 범위 밖

- 효과음 파일 다운로드·네트워크 요청
- 사용자별 서버 음소거 설정
- 장소별 다른 음원·배경 음악
- 점수 계산 또는 리더보드 API 변경
