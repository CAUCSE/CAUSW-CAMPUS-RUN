# 중앙대학교 캠퍼스 타이핑 게임 설계

## 목적과 범위

학교 축제 부스의 공용 PC 1~2대에서 운영하는 웹 타이핑 게임이다. 플레이어는 중앙대학교 서울캠퍼스의 실제 건물·장소명을 순서대로 정확히 입력해 코스를 완주한다. 기록은 CAUSW 백엔드 API로 저장하고, 게임과 관리자 페이지에서 당일 리더보드를 확인한다.

범위에는 게임 웹 화면, 타이핑 규칙, 게임 기록 API, 공개 리더보드, 관리자 기록 관리가 포함된다. 전공 용어·캐릭터·모바일 플레이·축제 이후의 다일 운영은 포함하지 않는다.

## 플레이 흐름

1. 대기 화면에서 당일 Top 10과 게임 안내를 보여 준다.
2. 플레이어는 학번과 공개용 별명을 입력한다.
3. 프론트엔드는 백엔드에 플레이 세션을 생성하고, 검증된 학번에 연결된 `sessionId`와 코스를 받는다.
4. 플레이 화면은 경과 시간, 현재 순번, 큰 장소명, 입력창을 중심으로 표시한다.
5. 12개 장소명을 모두 정확히 입력하면 결과를 서버에 저장하고 완주 시간·오타 수·당일 순위를 표시한다.
6. 플레이어는 바로 재도전하거나 대기 화면으로 돌아간다.

## 게임 규칙

- 기본 코스는 실제 중앙대학교 서울캠퍼스의 장소명 12개다.
- 모든 플레이어는 같은 12개를 사용하되, 각 세션의 순서만 무작위로 섞는다.
- 입력 대상은 건물 번호가 없는 장소명이다. 예: `전산정보관`.
- 입력은 글자 단위로 즉시 검증한다. 오타 글자는 빨간색으로 보이며, 수정되기 전에는 다음 글자나 다음 장소로 진행할 수 없다.
- 장소명 전체가 일치하면 자동으로 다음 장소로 넘어간다.
- 제한 시간은 두지 않는다. 완주에 걸린 경과 시간을 기록한다.
- 순위는 완주 시간 오름차순, 동점이면 오타 수 오름차순이다.
- 동일 학번은 재도전할 수 있지만 공개 리더보드에는 해당 사용자의 당일 최고 기록만 노출한다.

초기 장소 후보는 영신관, 파이퍼홀, 수림과학관, 학생회관, 본관, 전산정보관, 서라벌홀, 중앙도서관, 봅스트홀, 제2공학관, 창업보육관, 중앙문화예술관, 법학관, 미디어공연영상관, 글로벌하우스, 블루미르홀, 100주년기념관이다. 실제 기본 12개와 표기 방식은 운영 전 확정한다.

## 화면 구성

### 대기 화면

- 게임 설명과 시작 버튼
- 학번·별명 입력
- 자동 갱신되는 당일 Top 10 리더보드

### 플레이 화면

- 게임 제목과 경과 시간
- 현재 순번: 예: `7 / 12`
- 크게 표시되는 현재 장소명
- 키보드 포커스를 유지하는 입력창
- 오타 수와 글자 단위 피드백

지도·캐릭터는 플레이 중 표시하지 않는다. 화면은 공용 PC의 16:9 해상도에서 타이핑 가독성과 속도 경쟁을 우선한다.

### 결과 화면

- 완주 시간, 오타 수, 당일 순위
- 최신 리더보드
- 재도전 및 대기 화면 복귀

## 백엔드 API

CAUSW 백엔드에 타이핑 게임 전용 API를 추가한다. 경로·인증 세부 규약은 기존 백엔드의 관례에 맞춘다.

### 세션 생성

`POST /typing-game/sessions`

- 요청: 학번, 별명
- 처리: 학번 검증, 플레이 세션 생성, 장소 순서 셔플
- 응답: `sessionId`, 12개 장소명으로 구성된 코스

### 기록 완료

`POST /typing-game/sessions/{sessionId}/complete`

- 요청: 완주 시간, 오타 수
- 처리: 세션 존재·미완료 상태·코스 정보를 검증한 뒤 기록을 저장한다.
- 응답: 저장된 기록과 당일 순위

### 공개 리더보드

`GET /typing-game/leaderboard`

- 응답: 별명, 완주 시간, 오타 수, 순위만 포함한 Top 10 및 필요한 최근 기록
- 학번, 내부 사용자 식별자 등은 절대 포함하지 않는다.

### 관리자 기능

기존 관리자 권한으로 전체 기록을 조회하고, 테스트·오입력·부정 기록을 삭제한다. 수상 후보를 확인할 수 있어야 한다.

## 데이터와 개인정보

- 학번은 사용자와 기록을 연결하기 위한 서버 측 식별 정보이며 공개 화면에는 노출하지 않는다.
- 별명은 공개 리더보드 표시에만 사용한다. 중복 별명은 허용하며, 서버 내부에서는 학번과 기록 ID로 구분한다.
- 각 기록은 세션, 사용자 식별 정보, 별명 스냅샷, 완주 시간, 오타 수, 완료 시각을 가진다.
- 리더보드 조회는 사용자별 당일 최고 기록을 기준으로 구성한다.

## 오류 처리

- 유효하지 않은 학번이면 게임을 시작시키지 않고 안내한다.
- 완료된 세션을 다시 완료하려 하면 서버가 거부한다.
- API가 연결되지 않으면 새 게임을 시작시키지 않고 재시도를 안내한다.
- 완주 기록 저장이 실패하면 결과 화면을 유지하고 재시도할 수 있게 한다. 저장 성공 전 순위는 확정 표시하지 않는다.

## 검증 계획

- 프론트엔드: 글자 단위 검증, 오타 수정, 자동 다음 문제, 타이머, 장소 셔플, 완료 화면을 테스트한다.
- 백엔드: 학번 검증, 세션 생성, 중복 완료 거부, 리더보드 정렬, 개인 최고 기록 계산, 관리자 삭제를 테스트한다.
- 통합: 게임 완료 후 순위 반영, 저장 실패 재시도, 1~2대 공용 PC의 동시 기록 반영을 검증한다.
- 현장 점검: 실제 16:9 공용 PC에서 키보드 포커스와 전체 시작-완주-재도전 흐름을 점검한다.

## 결정 사항

- 플랫폼: 웹 브라우저, 공용 PC 1~2대
- 테마: 중앙대학교 서울캠퍼스 탐험
- 플레이: 고정된 12개 장소명의 무작위 순서 완주
- 입력: 장소명만, 글자 단위 강제 수정
- 기록: 제한 시간 없이 완주 시간 측정
- 공개 표시: 별명만
- 저장·관리: CAUSW 백엔드 별도 API와 관리자 페이지
